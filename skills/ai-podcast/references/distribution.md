# 平台分发与可核对结果

## 先做好发布包

在单期 release 新版本目录准备：平台可接收的音频、封面、标题、完整介绍、基于最终音频的 OUTLINE，以及用户/节目配置指定的 LINKS 和 CONTACT。链接/邮箱来自当前配置，不用开发者或历史任务身份填空。涉及图像时调用环境可用的适当工具；不假设订阅账号、节目归属或固定集号。

保留无损母版、逐段合成记录和 QA；发布包只收实际上传的文件与说明。用 `scripts/release_manifest.py create --root release/v1 --output release/v1/manifest.json` 固定候选文件哈希。不要把 credentials、原声、私有 voice profile、缓存和原始内部素材放进发布目录。

候选审阅完成且授权覆盖目标后，才执行外部写入。用户已经明确授权相同候选、平台、账号与动作时继续，不重复确认。未获授权时先把成品和各平台文案做具体，再提出一次针对该候选的请求；建立 Skill 本身不授权真实发一集。

授权本地记录可为 JSON：`candidate_sha256`（manifest 的字节哈希）、`platform`、`account`、`action`（upload/publish/submit-feed）、`evidence`（用户原话及任务消息定位）。脚本 verify 可核验匹配，但字符串证据仍需执行 Agent 对照真实会话，不能自行编造批准。

## 登录和发布

使用可用的平台官方连接器或浏览器；沿用当前工具实际可见的页面定位元素，不硬编码页面按钮和过时尺寸规范。先核对账号标识、节目名、所属区域、已有单集以及平台当前文件限制。缺登录态时走正常登录；密码不写脚本，扫码/MFA/CAPTCHA 由用户完成。关键账号不确定时暂停该平台，其余授权内准备工作继续。

| 平台类型 | 流程与证据 |
|---|---|
| Firstory 等 RSS 托管源 | 上传该候选、填写介绍/封面、按授权保存草稿或发布；记录平台单集 ID、真实 GUID、RSS enclosure 和页面链接，核对实际音频 |
| Apple Podcasts 等 RSS 目录 | 确认目标账号/地区及节目归属。已有相同源订阅时查同步，不重复新建节目；需添加源才执行 submit-feed。记录已提交/审核中/目录可见及地区证据 |
| QQ 音乐/TME/懒人 | 根据当前创作者后台和节目归属分别处理；页面证明联动才记录多个渠道成功，不猜一次上传自动全分发 |
| 喜马拉雅 | 核对当前专辑及账号，上传或已有源同步按后台实际模式执行；查看审核与可播放页面 |
| 用户另选的平台 | 核对官方支持的文件/RSS 方式和账号后执行，不由 Skill 自动扩大发布范围 |

每次提交前重新 `verify` 哈希，记录 intent（候选、账号、平台、动作、时间）。点击后网络报错/超时，先到列表/RSS检查是否已生效再重试；结果不明时标记 uncertain，避免重复单集。检查已有 GUID、平台 ID、标题、时长，不单凭同名判定是当前版本。

## 成功层次与交付

按实际证据记录每平台 `draft / uploaded / reviewing / published / playable / indexed / region-visible / failed / uncertain`，这些状态不全是线性步骤；只写已观察到的事实及时间。RSS/enclosure 相同可核对文件哈希；平台二次转码后用时长、开头/关键段试听和元数据核对，不要求转码后字节与母版一致。

用户需要时给出平台链接和失败的可执行下一步；不会因为“已提交”宣称 Apple 中国区上架。不能访问外部网页或登录受阻，交付发布包、停留步骤及具体原因；不伪造发布 URL，也不无限重试。归档不改变发布授权；定时监控必须由用户另外要求，并先检查已有监控避免重复。
