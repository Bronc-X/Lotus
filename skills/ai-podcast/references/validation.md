# 验证范围

2026-09-23：此包从一次已确认的中文单人口播及后续多平台分发经验抽出。不是对所有电脑、说话人、语言和平台完成一次新的端到端验收。

## 已实测

- Windows，PyTorch 2.8.0+cpu：使用测试用声线 profile，以 CPU float32 / 32 步生成 2.625 秒音频；脚本记录 77.562 秒（含加载等开销）。检查非静音、有限样本、24 kHz 单声道、无削波及产物哈希通过。这说明此环境可在 CPU 跑通，不能承诺实时生成或继承任何声线的听感批准。
- 同一 CPU 环境：从 9.9 秒人工原声片段和精确逐字稿创建新的候选 profile，保存原声与 prompt 的 SHA256；编码阶段 4.61 秒。未将此测试候选替代原来已批准的声线。
- 新建候选 profile 再合成 2.614 秒短样成功（74.625 秒）；原 profile 的相同任务重跑返回 reused，输出哈希保持一致。
- 离线合同测试覆盖设备选择与显式设备不可用报错、镜头时长上限、设备变化不能复用旧指纹、发布文件篡改检测、不同账号/动作的授权不匹配。`python scripts/self_test.py`。
- Skill frontmatter/名称/结构用 skill-creator 的 quick_validate 检查。
- 2026-09-24 更新为跨说话人的表达提示命名；`python scripts/self_test.py` 共 9 项通过，覆盖输出与源文件冲突、排他锁、非法数值、声线身份、设备、缓存与发布清单约束。
- 同日 Windows CUDA / PyTorch 2.13.0+cu130：Toni、Brian 和通用入口分别生成 5.35、6.31、5.35 秒短样，24 kHz 单声道，峰值不超过 0.90；解码、有限样本、非静音、SHA256 与相同任务重跑复用通过。不同说话人使用各自本地 profile；这些短样仅作技术验证。
- Lotus 仓库的 4 项跨技能测试、Windows/Bash 私人配置保留安装测试、PowerShell 同步与重复运行测试、完整安装器回归通过。原声 recording 脚手架的正常 QA 通过；未获授权却声明可发布的状态被拒绝。
- `quick_validate.py` 结构校验通过；此校验不证明任意新说话人或平台的端到端效果。

## 验证边界

- MPS 路由基于 OmniVoice 官方源码；路由分支有模拟测试，未在 Apple Silicon/Intel Mac 实机生成音频。必须目标机 doctor/短样测速后才能宣称该机可用。
- 本次 CPU 短样是运行性与数值检查，不是用户对新设备听感的批准；中文短样不能证明英文质量或长稿无误。
- 文字处理是 Agent 工作流，不是纯脚本自动事实核查；需要遵循实际材料与用户目标执行。
- 分发流程未在本次 Skill 创建任务中真实上传；只有具体节目任务得到授权后才能执行并核验。发布包哈希测试不等于平台发布成功。
- 不使用 VERIFIED 标记代表全流程、所有平台或独立验收均通过。
