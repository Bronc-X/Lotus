# 网页与成片恢复

以当前平台页面为准，用 Agent 可用的浏览器工具进行可见页面操作；不抽取 Cookie、不逆向私有接口。若当前工具不能下载，保留同一任务与卡片，不重新付费提交；可让用户保存已有成片后提供文件。

## 上传与计费

- 确认模式接受原视频编辑，不是只接受图片的关键帧入口。当前界面标签、上传限制和模型可用性要现场核对；不将旧 API 的输入限制套到新网页。
- 只上传 `inputs.uploadVideo` 一个视频，五张 `inputs.identities` 按 `referenceOrder` 全部上传；源 `source` 用于原声和时长，不能把它额外上传为第二段内容。
- 素材分工应是五张照片定义目标面部身份与自然纹理，原片定义表情、动作、口型、身体、场景和成像条件；这不保证编辑入口执行身份替换。若原片有多人，明确只改哪位主角。
- 核对鼻型、眼型和脸轮廓是否确实来自目标。避免“保持原脸”“不改变脸型”等会压制身份替换的负向语句。保持皮肤自然不等于沿用原人物五官。
- 按实际 UI 模型、账号和费用确认本次授权；历史单次费用只是历史，不是新的预算或费率。UI 仅显示排队时记录排队，未提交不写生成中；HTTP成功、卡片出现和真正成片分开。

官方入口可供核对：[Kling用户指南](https://kling.ai/quickstart)、[Kling 4.0指南](https://kling.ai/quickstart/kling-4-model-user-guide)。这些链接是发现入口，不替代当前账户与页面实际支持。

## 恢复与身份判定

生成状态不明时先查同一已提交卡片/任务。下载错误不代表生成失败；不重付费提交来修下载。记真实 `taskId`，未知为 `null`；可见创作卡片编号记 `creationResourceId`，不能冒充任务ID。

从聊天工具接收的视频可能仅重封装，也可能转码。记录来源；完整文件 SHA256 相同可证明字节相同，视频码流相同可证明编码视频负载相同，二者不能混用。多个候选比较内容和回执，不凭“最新”“final”选片。

`complete.py` 保留提交回执并冻结收到的文件 SHA256。原下载字节没有独立核对时 `platformOriginalBytesVerified=false`；`user-supplied-remux` 明确表示经过用户通道取得的重封装文件。收集当前文件是技术接纳，不自动确认人脸质量。

## 身份未替换时

“全能参考”接收五张图，只能证明参考素材齐全，不能保证目标身份锁定。即使页面生成、下载和 Build/Result 均已完成，输出仍可能沿用原脸。包内 Provider 负责本地等待、回执与文件收集，不是专用换脸或身份锁定 Provider。

- 用户或视觉检查否决目标身份时，记录“身份替换未通过，任务未完成”，保留实际生成与下载回执；不要把身份失败改写成下载故障。
- 停止在同一入口仅靠加强提示词重复整段付费。先核对当前可用工具是否实际支持专用身份替换、身份约束或局部人脸编辑；未核实前不宣称已有可用方案。
- 若要继续生成试验，先明确样片范围和费用授权，用短样片或关键帧检查目标鼻型、眼型、脸轮廓及正侧面一致性。关键帧通过后仍须用短视频检查转头、遮挡和连续身份稳定；身份验收通过后再讨论整段生成。

匿名真实案例：一次长视频编辑实际上传了全部五张独立目标图，生成、下载与本地收集均完成，输出却主要沿用原脸。用户否决成片，本地抽帧也确认目标身份未采用。该次换脸任务未完成，问题属于身份替换失败，不属于下载失败；素材数量齐全和技术链路通过均不能推翻这一判断。

## 音画与视觉检查

`finalize.py` 的整体轻微 retime 只统一总时长和帧数。视频时钟来自 `--timing-source`（默认 `--source`），音频始终来自 `--source`。脚本检查实际帧 PTS；VFR 或不规则时钟不能按 `frame_count/avg_frame_rate` 均匀化，须提供保留原始 PTS 节奏的 CFR 兼容副本。制作这种副本时用基于 PTS 的 `fps=30:start_time=0:round=near` 等重采样；不能先 `setpts=N/(fps*TB)` 把原有快慢段抹平。重采样帧率按任务选择，副本的时长、内容和原片对应关系仍需核对；两份哈希与音画依据进入QC。播放检查转头、遮挡、脸部边缘、鼻型侧面、眼型、表情、口型和背景稳定性。源音频复制后核对每个编码 packet 的 payload hash；AAC回退会改变 payload，必须记录差异。联系图只覆盖采样帧，不能代替连续播放。

## 左右比较

只有用户要求时制作。先确认左右各是谁，不能把两个生成版标成“真实原片”。对齐可以依据相同帧号、动作事件或明确偏移；标清实际口径。总时长相同、帧数相同或全局retime均不能证明模型表演逐帧相同。保留源尺寸比例，避免压扁脸；选择一个音轨，不能把左右音频叠加造成回声。导出后核对帧数、标签、顺序和播放。
