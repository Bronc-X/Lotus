# Web design

## Direction

Define a clear thesis using the smallest useful set of choices: type character, palette roles, layout rhythm, imagery, material, and motion. Use the user’s brand and content before introducing a new aesthetic.

Avoid default template habits such as interchangeable centered heroes, repeated equal-card grids, generic AI gradients, excessive glass effects, fake dashboards, decorative statistics, and filler slogans. These are warnings, not bans; use a familiar pattern when it is the clearest fit.

## Implementation

- Establish a visible hierarchy and one primary action per decision point.
- Vary composition and density across sections while keeping spacing, typography, and controls consistent.
- Make asymmetric and multi-column layouts collapse intentionally on narrow screens.
- Use the project’s icon family and dependency conventions.
- Provide real loading, empty, error, disabled, hover, focus, active, and reduced-motion behavior where the feature actually needs those states.
- Keep visible copy concrete and consistent. Do not invent customer names, metrics, testimonials, awards, or product capabilities.
- Meet readable contrast and touch-target expectations. Preserve semantic structure and keyboard access.

## Visual check

Run the local app through its existing command. Inspect at least one representative desktop width and one narrow mobile width when the page claims responsive support. Check image loading, overflow, clipping, stacking, contrast, dead controls, console errors, and reduced motion. Fix problems caused by the change and recheck the affected views.
