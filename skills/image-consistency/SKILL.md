# 生图一致性skill

将当前项目的参考素材转成可验收的最终图片。使用随 Skill 提供的脚本，项目素材、提示词、审核记录与产物留在当前项目；不依赖原始项目或个人应用配置。

## 范围与路由

- 主路径：已批准的 SKU 商品事实和人物参考 + 当前商品实拍 → 候选图 → 逐项商品审核 → 批准的最终图 → 批量换款或构图。
- 仅商品、多人物、无参考从零生图、第三张姿势参考属于需要单独验证的分支。没有身份参考时先建立并批准身份基准，不声称一次提示词能保证后续身份一致。
- 接口支持与调用方式读 [references/api.md](references/api.md)；编写具体提示词时读 [references/prompts.md](references/prompts.md)。
- 商品最终图需要强制绑定原图、SKU 事实与审核结果时读 [references/sku.md](references/sku.md)，使用随附 `scripts/sku_gate.py`。
- 需要判断已验证范围、换服务商或更新 Skill 时读 [references/validation.md](references/validation.md)。现有实测是单项目双参考样例；不能宣传为跨企业验证、零漂移或全局最优。
- 用户要求视频时只交付已验收的独立首帧；视频需转交当前项目的视频流程。

## 执行

1. **确定本次任务。** 从当前对话和项目读取目标图片、商品事实、人物基准、构图、尺寸、张数、输出位置、模型及已有授权。信息已有就直接复用；只询问会改变结果的缺项。新项目不得自动沿用其他企业的素材、凭据或预算。
2. **建立项目记录。** 可从 [assets/job.example.json](assets/job.example.json) 创建任务单。它是给执行者阅读的记录模板，不是脚本自动加载的配置。商品最终图另从 [assets/sku-contract.example.json](assets/sku-contract.example.json) 建立 SKU 事实单，经商品负责人确认后才可由 SKU 门禁执行。路径相对项目根目录解析。建议产物存 `image-consistency/<任务名>/`，可遵从项目既有目录；Skill 目录保持只读，不在其中保存客户数据。
3. **查看原图并分配角色。** 逐张打开人物和商品素材，列出可见的身份特征、商品颜色、结构、材质、标识位置及不可变细节。看不清的文字标记为待确认，不能补造。将参考角色映射到实际上传顺序，提示词与 `--reference` 顺序必须一致。可选姿势图仅提供动作和构图；不要继承旧款衣服或另一个人的脸。
4. **检查接口与输入。** 使用当前项目明确授权的第三方 API，配置从进程环境变量读取。检查实际模型 ID 和接口协议。沿用本项目已经完成的有效检查，不为每张图重复测试。模型列表成功不代表编辑能力通过。只检查凭据是否存在，不输出值；不得从旧对话、Codex 配置或其他项目寻找密钥。
5. **生成代表样图。** 商品最终图先用 `scripts/sku_gate.py prepare` 检查 SKU 审批、原图哈希与特征，再检查生成的提示词，使用 `generate` 调用图片接口；具体命令见 [references/sku.md](references/sku.md)。每次一张、唯一任务目录。尺寸、质量、背景、摄影风格由本次需求决定；1024×1536、白底和任何模型名都不是全局固定值。付费提交按当前用户已经给定的服务、数量及预算授权执行，不重复询问已有授权，也不擅自扩批。
6. **视觉验收。** 打开实际输出并与原图并列对照：人物五官/发型/比例；商品结构/颜色/材质/配件/标识；姿态与人体结构；构图与背景；实际像素尺寸。小字、logo、缝线及销售关键部位需查看局部细节。无法确认的项目标为待审核；缺少视觉能力时保留待审核状态，不能仅凭回执判断合格。将结果记入项目中的 `quality-review.json`，逐项绑定输出哈希与审核意见；全部通过后执行 `sku_gate.py release`，下游只使用 `verify` 返回的批准资产。
7. **定向修正或扩批。** 不合格时明确哪一项失败，调整相关提示词或参考，并保留前版和回执；额外付费次数超出既有授权时再问用户。出现重复同类失败、素材矛盾或预算耗尽时停止，给出具体缺口。代表样图经过当前任务约定的审核后再扩批；用户已指定样图可沿用。每个 SKU 回到原始商品参考，避免只用上一张生成图逐代转绘造成漂移。
8. **交付。** 给出可打开的最终图片路径与预览、采用的提示词/模型参数、生成回执和简短质量结论。技术成功但审核未完成的图片明确标为待审核，不列为最终批准图。不得把 API 成功、模型显示名或一次视觉观察当成准确率保证。

## 失败与重跑

- 脚本不自动重试付费 POST。超时或 `UNKNOWN` 先核对该次回执和供应商任务/扣费状态，再决定新尝试，不能直接重发。
- `OUTPUT_UNAVAILABLE` 用 `media_api.py recover --output 原输出路径` 恢复同一次已生成结果，不立即另付费生成；如未保存结果或供应商 URL 失效，按回执和供应商标识对账。`NOT_SUBMITTED` 修复本地配置/输入后再提交。
- 不覆盖既有图片或回执。不把 API 地址、密钥、签名下载 URL 写入可分享任务单或日志；下载图片不携带 API Authorization。
- 同步兼容协议以外的接口先适配并测试；不能只替换 base URL 就承诺可用。

## 完成门槛

输入与提示词可追溯；图片确实存在且可解码；实际尺寸符合需求；内容检查及待确认项已经记录；产物属于当前项目；没有把未验证分支描述成已验证。只有达到当前项目内容标准的图片才称为最终图。
