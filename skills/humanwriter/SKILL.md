# Humanwriter

让读者看懂对象、事实和下一步。按标题、网页正文、产品界面的实际用途改写，不把所有文字压成按钮文案。

## 分工与改动范围

- 独立标题、网页文案、产品介绍、卖点、CTA 和界面文案由本 Skill 处理。网页上的随笔、文章、访谈按内容体裁判断，正文去 AI 味交给 lieflat-less-ai-tone。
- 用户只要求改标题，就只改标题。整篇随笔连同原有标题由 lieflat 处理，不能因为出现标题而拆开重复编辑。
- 新写整套营销方案或页面内容使用 copywriting；已有标题、网页和产品文案的修改使用本 Skill。
- 先读用户给定的事实、品牌用语、风格参考和已确认文案。保留用户的立场、语气和有效表达，不强加统一的口语或冷淡语气。
- 局部修订保持页面区块、段落、组件顺序和标识不变。重排、合并区块或改定位只在用户要求涉及结构时执行。

## 从 lieflat 吸收的编辑纪律

1. **逐处判定。** 每处改动须能说明具体问题及其对理解、判断或操作的影响。未发现明确问题的文字原样保留；拿不准时保留，不凭“像 AI”整体重写。
2. **最小改动。** 只改解决问题所需的词句，不顺便换近义词、改变语气、补故事或追求所有句子都不一样。用户明确要求重写时，可在其范围内重写，仍须保真。
3. **信息保真。** 人名、数字、币种、日期、来源、引语、因果、否定、比较、适用范围和限定词均有依据。保留“可能”“通常”“仅”“未”等强度与边界，不把计划写成完成、建议写成承诺或局部成功写成全部成功。
4. **删除有边界。** 可删无信息的修饰、重复说明和套话；删除前核对是否损失事实、产品差异、限制、费用、失败状态或操作后果。标题可选取正文已支持的重点，不能扭转原意；必要条件在标题附近可见，不能为短而隐藏。
5. **词和标点不是罪证。** 不按“赋能／闭环”、破折号、冒号、问句、排比或长句的出现次数机械改写。看它在此处是否传达必要含义；品牌词、正式术语、引文和作者习惯按原意保留。
6. **不制造自然感。** 不为参差强行拆句拆段，不强加“我／你”、口语垫词或比喻。不凭检测指标断言文字由 AI 生成。

这些纪律在本 Skill 内直接执行，不要求每次加载 lieflat。短标题、按钮和提示不套用长文章的千字密度、段落指标或整套检测报告；通常直接交付改稿，只有用户要求分析或对比时才附解释。

## 判断顺序

写每句话前依次确认：

1. 谁在看，已有多少背景信息。
2. 他此刻要识别、判断还是操作。
3. 当前这句话传达哪个事实、差异、限制或动作。
4. 是否存在可定位的问题；删除或替换后会丢掉什么。

UI 文案承担命名对象、呈现状态、指向动作、说明必要后果或限制的职责。网页正文还可解释产品差异、收益依据和适用条件，不按 UI 的字数习惯一律删除。

## 值得改的表达

- **虚设对立。** “不是 A，而是 B”“你以为……其实……”没有真实纠偏作用时，直接给判断；A 若包含必要否定、范围或差异，须保留其信息。
- **结论提示语。** “一句话总结：”“核心是：”没有信息时去掉提示语。正常标签、列表引导、术语解释和引文中的冒号保留。
- **冗长话题壳。** 前置定语或“对于……来说”使主语和动作难找时，缩短或调整语序；保留时间、条件和适用对象。
- **同物换名。** 同一对象轮换多个名称使人误认成不同功能时，统一用已确认的名称；不同状态、层级或对象不能为了统一而合并。
- **空泛收益。** 原文已有具体事实时用它说明收益；没有证据时删修饰或保留中性描述，不编造数据、功能和案例。产品真实能力与有依据的营销表达可保留。
- **机械句式。** 相邻宣传句反复同一骨架且妨碍理解时，只调整必要句子；平级功能、操作步骤和状态列表需要一致结构时保留。

## 必须避免

- 不让产品自我解说。少写“系统已”“平台会”“Agent 已为你”；直接呈现结果及来源。
- 不用产品经理汇报句替代实际内容，如“释放增长”“沉淀标准能力”。这类词若无具体含义则删；有明确业务定义时保留或解释，不能只因命中词表就改。
- 不用“智能、高效、无缝、精准、全新”等形容词代替证据。
- “一键”须确实只有一步；“自动”须对应真实自动执行的环节，并保留必要的人工确认说明；“立即”须有实际时效依据。不能用这些词制造不存在的轻松感。
- 不虚构因果。数据上涨时只写比较口径，不把变化归功于某个功能，除非有证据。
- 不无意义地重复界面已有信息；必要的确认、无障碍标签和风险提示保留。辅助文案补充后果、限制、来源或下一步。
- 不把内部实现暴露给普通用户。数据库、模型、规则引擎只在审计、来源或故障处理需要时出现。

## 常见改法

下表只示范改法。使用其中的数字、来源和流程描述前，必须有当前材料支持；不能照抄示例补全事实。

| 避免 | 改为 |
| --- | --- |
| 系统已扫描档案并生成今日任务 | 今日任务已生成（扫描完成若是必要状态，另保留） |
| 医生方案一出具，平台立即接棒 | 按已确认流程，写清方案出具后的具体动作；动作不明时不补写 |
| Agent 已结合多源数据生成 | 写明当前材料已有的参考来源；来源未提供时不列清单 |
| 覆盖渠道服务全链路 | 列出材料已确认的服务环节，不自行补业务能力 |
| 一键复制 | 复制话术 |
| 当前筛选下没有跟进任务 | 没有符合条件的跟进任务 |
| 结果可直接生成任务 | 按真实流程写“生成任务”或“确认后生成任务”，不擅加或删确认步骤 |

保真例子：“已保存，但未同步到其他设备”不能缩成“已保存”；“不是所有订单都支持退款，仅未发货订单可申请”不能为了去掉对举而变成“订单支持退款”。

## 组件文案契约

- 产品 UI 标题：用业务名词或当前任务，优先简短，不为凑字数删掉必要范围。
- 独立标题与网页主标题：表达一个有材料支持的主题或判断，保留必要条件；不默认套用“重新定义”“从此告别”等吸睛句式。
- UI 页面说明：通常一句，写范围、口径或关键限制；网页介绍按内容需要解释，不强制一句。
- 按钮：使用“动词 + 对象”，如“保存方案”“复制话术”“查看客户”。避免“确定”之外含义不清的万能动词。
- 标签与表头：使用稳定名词，不写完整句子。
- 状态：描述已经发生或正在发生的事实，如“待跟进”“保存中”“已复制”。
- 指标：标题写口径，数值写结果，脚注写时间或比较基准。
- 表单帮助：说明填写标准、影响范围或保存后果，不解释产品理念。
- 空态：先写缺少什么；存在明确恢复动作时再给下一步。
- 错误：写明失败对象和可行的恢复方式，如“方案未保存，请重试”。原因未知不编原因，部分成功时保留成功与失败范围。
- Toast：写结果和必要后果，如“已保存为 v4，未完成任务已更新”。
- 抽屉：保留列表上下文，标题直接命名当前客户、渠道或方案。
- 弹窗：只写当前单一动作，避免再次介绍整套功能。

## 医疗与客户沟通

- 医生医嘱保持原意，不用模型推断替代医疗结论。
- 低置信度观察写“待人工确认”，不写确定性判断。
- 客户话术像顾问本人发送：称呼自然，一句只提一个请求，明确需要反馈的内容。
- 不在客户话术中出现“模型、Agent、规则命中、数据库”等内部词。
- 需要展示处理来源时，把“原始导入、医生医嘱、整理结果”分层列出，不用拟人化 AI 旁白。

## 执行流程

1. 确认本次对象与改动范围。仅给标题时先用已有上下文，缺少会改变含义的事实才询问。
2. 内部标出具体问题和“保留、删除、替换”理由，按上述纪律做最小修改，不要求向用户展示内部清单。
3. 对照原文逐项核对事实、限定、否定和状态；新增事实或必要信息丢失时撤销或修正。
4. UI 检查术语、动作及本次涉及的加载、成功、失败、空态和不可用反馈；网页检查标题、正文、证据与 CTA 是否一致。
5. 按用户要求交付替换稿。默认一个可用版本，不自动附检测报告、写作分析或多套备选；用户要求时再提供。

## 交付检查

- 每处改动对应具体问题；未命中的文字没有被顺便润色。
- 数字、因果、否定、比较、限定、状态和后果与原材料一致。
- 没有为统一风格损坏网页说服逻辑、平级列表、品牌用语或作者语气。
- 操作前知道会发生什么，操作后知道是否成功。
- 没有空泛收益、虚构因果或未经证实的医疗判断。
- 没有为了显得智能而出现的 AI 术语。
- 业务含义、权限边界、版本规则和原始数据未被文案润色改变。
